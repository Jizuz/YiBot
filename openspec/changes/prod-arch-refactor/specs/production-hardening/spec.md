# 规格：生产化底座（production-hardening）

## 能力概述

为系统提供生产化工程底座：统一响应与异常规范、含链路标识的结构化日志、模型调用参数可配、编排递归上限、配置集中管理、四层目录归位与工程卫生清理，使代码结构可维护、行为可观测、变更可审计。面向开发、测试与运维角色（对终端用户行为无变化）。

## 业务前置条件

- 三条业务链路（问诊/科普/权益）改造前行为正常，作为回归基线；
- 编排层（主控+子智能体+状态结构）为平移对象：**零逻辑改动**，仅位置与装配方式变化；
- 历史会话数据与会话标识格式保持可用（见 `access-auth` 数据约束）。

## 输入定义

| 名称 | 类型 | 是否必填 | 说明 |
| ---- | ---- | -------- | ---- |
| 运行配置 | 部署配置 | 是 | 原 30+ 散落环境变量收敛为集中配置（含密钥、模型参数、超时、配额等） |
| 业务请求 | HTTP 流量 | 是 | 全部对外接口，走统一响应/异常规范 |
| 编排调用 | 内部调用 | 是 | 问诊编排执行，受递归上限保护 |

## 输出定义

| 名称 | 类型 | 说明 |
| ---- | ---- | ---- |
| 统一响应结构 | 响应规范 | 全部接口一致的成功/失败结构（业务码+消息+数据） |
| 统一异常响应 | 响应规范 | 未捕获异常兜底为统一结构，不泄漏堆栈细节 |
| 结构化日志 | 可观测数据 | 含链路标识（trace_id）的机器可读日志，替代散落 print |
| 归位后目录结构 | 工程结构 | 接入/编排/模型/工具/数据分层，依赖方向单向 |

## 主流程（正向链路）

1. 请求进入：中间件生成/透传链路标识，全链路日志携带该标识；
2. 业务处理：各层按依赖方向单向调用（接入 → 编排 → 模型/工具 → 数据），禁止反向；
3. 响应返回：统一结构包装；异常由全局兜底转为统一错误响应并记录日志；
4. 模型调用：超时、重试次数、温度等参数从集中配置读取，行为可调不改码；
5. 编排执行：受递归上限保护，超限时明确失败而非失控循环。

## 分支场景

- 调试入口保留：简易对话/简易智能体等调试通道随层归位，不删除；
- 提示词集中管理：原散落硬编码的 6 处提示词收敛到统一目录并版本化（内容不变，为审计快照打基础）；
- 会话检查点组件随数据层归位，连接参数全部走配置（去除硬编码地址）；
- 模型装配时机后置：由应用启动阶段统一构造注入，支撑单测替身（mock）。

## 异常场景 & 业务错误码

| 场景 | 错误码 | 业务表现 |
| ---- | ------ | -------- |
| 业务校验失败 | 4xx 业务码 | 统一结构返回业务码+可读消息 |
| 未捕获系统异常 | 500 | 统一兜底响应，日志含 trace_id 可追查，不外泄堆栈 |
| 编排超出递归上限 | 5xx 业务码 | 明确失败响应（防失控循环），日志记录 |
| 数据访问异常 | 5xx 业务码 | 异常上抛转统一响应，**禁止吞错返回空结果** |
| 模型调用超时/重试耗尽 | 5xx 业务码 | 按配置重试后失败，明确提示 |

## 数据约束

- 数据访问统一会话生命周期管理：异常必须上抛，不得静默返回空值掩盖故障；
- 落库操作由无上限的裸后台线程改为受控异步任务：失败必须可观测（日志/重试），不得静默丢消息；
- 表结构变更统一走迁移工具管理，禁止手工改库；
- 配置单一来源：任何配置项只在一处定义，散落读取收敛。

## 权限与数据隔离

- 本能力为横切底座，不引入新业务权限；数据隔离遵循各业务能力规则；
- 错误响应不泄漏内部实现细节（地址、密钥、堆栈）。

## 并发与重试规则

- 异步客户端全链路使用（缓存/计数/会话管理），禁止在异步路由中调用阻塞式客户端阻塞事件循环；
- 模型调用重试次数/超时可配，默认值保守，重试幂等（问诊调用无副作用累积）。

## 业务容量约束

- 编排递归上限默认值可配置（防止异常场景无限循环）；
- 单次问诊请求整体超时可配（替代当前无超时阻塞）。

## 验收用例（测试要点）

✅ 正向用例
- 三条业务链路（问诊/科普/权益）端到端回归通过，行为与归位前一致（零逻辑平移验证）；
- 全部接口响应结构统一；日志为结构化格式且全链路携带同一 trace_id；
- 模型超时/重试/温度通过配置调整即生效，无需改码。

🔄 边界用例
- 空文件/空目录/根目录测试脚本清理后，工程构建与测试入口仍完整；
- 双向量库并存现状保持（仅目录归位，检索行为不变）；
- 调试入口归位后可正常使用。

❌ 异常用例
- 依赖方向静态检查：不存在反向/跨层违规引用；
- 数据访问异常时接口返回统一错误（不再返回空列表假成功）；
- 编排超递归上限：明确失败而非挂死；
- 代码中无 print 残留（日志统一出口）。

## 兼容与灰度规则

- 目录归位采用纯平移：模块路径变化对外部调用方零影响（入口路径不变）；
- 归位放实施序列最后阶段，避免与业务改动叠加冲突；
- 配置集中后保留环境变量同名兼容读取（部署零改造平滑过渡）。

## 业务埋点与告警指标

- trace_id 贯穿率（请求→编排→模型→数据）；
- 模型调用失败率/超时率/重试命中率；
- 异步落库任务失败量（突增告警）；
- 工具网关调用统计（成功率/熔断事件）可观测。

## 规格备注

- 本能力对终端用户无可感知行为变化，验收以"回归一致 + 结构约束 + 可观测性"为口径；
- 与其他能力关系：为 `access-auth`/`llm-token-quota` 提供配置集中与统一响应底座；`security-hardening` 的表结构清尾（明文列删除）依赖本能力的迁移工具；
- SSE 流式响应本期不交付（仅网关参数预留），流式化后本能力需补充流式日志与超时口径。
