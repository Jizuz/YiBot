# 规格：LLM 用量配额（llm-token-quota）

## 能力概述

对全链路大模型调用进行 token 用量计量，按用户按日设置配额：用量入账、超限前置拦截并友好提示、当日用量可查询，实现 LLM 成本可控。面向患者用户（用量受约束）、运营/管理方（配额调整与观测）。

## 业务前置条件

- 用户已通过鉴权（身份从令牌获取，见 `access-auth`）；
- 计量覆盖**全部**大模型调用点：主控路由、分诊/症状/科普/权益四个子智能体、记忆折叠等，不遗漏、不重复计数；
- 配额按自然日计算，跨日自动重置。

## 输入定义

| 名称 | 类型 | 是否必填 | 说明 |
| ---- | ---- | -------- | ---- |
| 问诊请求 | 业务请求 | 是 | 触发一次多环节大模型调用的用户提问 |
| 配额查询请求 | 业务请求 | 是 | 查询本人当日用量/剩余 |
| 配额配置 | 管理配置 | 是 | 每用户每日 token 上限，可调整 |

## 输出定义

| 名称 | 类型 | 说明 |
| ---- | ---- | ---- |
| 当日用量累计 | 计量数据 | 按用户按日累计的 token 消耗总量 |
| 剩余配额 | 计量数据 | 当日额度减已用量 |
| 超限拦截响应 | 429 业务码 | 超配额时前置拦截，附友好话术，不进入问诊编排 |
| 用量预警提示 | 业务提示 | 剩余量低于阈值（默认 20%）时随回复提示 |

## 主流程（正向链路）

1. 用户发起问诊：入口先检查当日已用量与配额；
2. 未超限：放行进入编排，各环节大模型调用结束后其 token 消耗异步入账（按用户按日累计）；
3. 用户查看配额：返回当日已用/剩余；
4. 剩余量低于预警阈值：回复中附带用量提醒话术。

## 分支场景

- 长对话单轮消耗大：单次调用不做中途打断，配额在下一轮入口拦截（保证单轮完整性）；
- 计量入账失败：不影响主流程（问诊正常返回），当日用量容差可接受，事后可对账；
- 管理端调整配额：即时生效，已用量不清零；
- 跨日：自然日切换后用量重新从零累计。

## 异常场景 & 业务错误码

| 场景 | 错误码 | 业务表现 |
| ---- | ------ | -------- |
| 当日用量达到配额上限 | 429 业务码 | 前置拦截，提示"今日咨询额度已用完，明日恢复"类话术，不产生新的模型调用 |
| 配额查询无当日记录 | 正常返回 | 已用 0、剩余=全额 |
| 计量数据异常（缺失/迟到） | 静默 | 查询按已入账数据返回，不报错 |

## 数据约束

- 计量键按"用户 + 自然日"隔离，历史数据保留 48 小时后过期（对账窗口）；
- 入账只增不减（异步累计语义），同一调用不重复入账；
- 配额调整不回溯修改历史用量。

## 权限与数据隔离

- 用户仅能查询本人用量与配额；
- 管理方可调整配额与查看全局用量统计（管理端能力，随配额配置下发）。

## 并发与重试规则

- 入口检查与入账为异步解耦：检查读"已入账量"，允许窗口内少量超放（先检查后入账的固有容差，可接受）；
- 拦截判定幂等：同一用户超限后重复请求均被拦截且不产生额外模型调用。

## 业务容量约束

- 默认配额 50000 token/用户/日（可配置）；
- 预警阈值默认剩余 20%（即已用 80%时提示）。

## 验收用例（测试要点）

✅ 正向用例
- 正常问诊后，当日用量计数随对话增长（覆盖主控+子智能体+记忆折叠全部环节）；
- 用量查询接口返回的已用/剩余与实际消耗一致；
- 剩余量跌破阈值时收到预警话术。

🔄 边界用例
- 调低配额至当前用量之下：下一轮问诊即被拦截；
- 跨日 0 点后再次问诊：用量从零重新计数；
- 单轮长对话消耗超过剩余额度：本轮完整执行，下一轮拦截。

❌ 异常用例
- 超配额请求：返回 429 业务码与友好话术，编排零调用（成本不再增长）；
- 计量入账通道故障：问诊主流程不受影响，恢复后继续累计。

## 兼容与灰度规则

- 配额能力提供配置开关：异常时可临时关闭拦截（仅计量不拦截）快速止血，需告警；
- 上线初期可设高配额观察计量准确性，再收敛至目标值（灰度策略）。

## 业务埋点与告警指标

- 每用户每日用量分布与全站日消耗趋势（成本观测）；
- 超限拦截次数、预警触发次数；
- 计量入账失败次数（突增告警）。

## 规格备注

- 与 `access-auth` 关联：配额查询接口复用鉴权；身份（uid）取自令牌；
- 与 `gateway-traffic-governance` 互补：网关拦请求量（429 网关层），配额拦用量（429 业务码），错误提示需可区分；
- 计量覆盖范围以"全部大模型调用点"为验收口径，新增调用点默认纳入。
